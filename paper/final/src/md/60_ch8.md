# 八、问题三：共享只读 L2 下的模型与求解

## 8.1 L2 语义与命中来源

官方问题三评估器在问题二的执行模型上增加一个所有核心共享的只读 Cache，规则可以归纳为四条：（1）只有 `COPY_IN` 查询 Cache，命中键是写入片上张量的逻辑编号；（2）是否命中在 `COPY_IN` 发射时判定，命中时以 $\mathrm{bw}_{\mathrm{L2}}=250$ B/cycle 读取，且不进入 DDR 带宽池；（3）未命中的 `COPY_IN` 走 DDR，完成时才写入 Cache；（4）容量 $C_{\mathrm{L2}}=1$ MB，按 FIFO 淘汰，命中不改变条目顺序，大于容量的张量不写入。

由此，一个张量能命中的前提是它此前已经被某个 `COPY_IN` 从 DDR 读入过。满足这一前提的只有两类读：一是同一张量被多个核心各自读入（图输入张量、跨核中间张量），第一次未命中并写入，之后的读可能命中；二是同一核心对同一逻辑张量的再次读入（释放后重读，或换出后换入）。定义张量 $t$ 的复用度与 Cache 价值为

$$\mathrm{reuse}(t)=\bigl|\{\text{对 }t\text{ 的 }\texttt{COPY\_IN}\}\bigr|,\qquad \mathrm{value}(t)=s_t\bigl(\mathrm{reuse}(t)-1\bigr)\,\mathbb 1\bigl[s_t\le C_{\mathrm{L2}}\bigr]$$ {#8-1}

$\sum_t\mathrm{value}(t)$ 是命中字节的上限。一次命中节省的搬运时间为 $s_t(1/\mathrm{bw}-1/\mathrm{bw}_{\mathrm{L2}})$，于是

$$\Delta T_{\mathrm{L2}}\le\sum_t\mathrm{value}(t)\Bigl(\frac1{\mathrm{bw}}-\frac1{\mathrm{bw}_{\mathrm{L2}}}\Bigr)=0.0127\sum_t\mathrm{value}(t)$$ {#8-2}

命中还不占 DDR 带宽池，等于把 DDR 争用降低了同样的字节数，这是 L2 的第二重收益，在带宽受限的用例上更明显。

上限能否达到取决于时序。把张量 $t$ 写入 Cache 之后、最后一次读 $t$ 之前写入 Cache 的字节数记为复用距离 $D_t$，FIFO 且命中不刷新时，$t$ 的后续读全部命中的条件是

$$D_t+s_t\le C_{\mathrm{L2}}\quad\text{且}\quad\text{后续读的发射时刻晚于首次读入的完成时刻}$$ {#8-3}

两个条件方向相反：读 $t$ 的各个核心相隔太远，$D_t$ 变大，$t$ 在被复用前就被淘汰；相隔太近，后面的读在前一次读入完成前就已发射，同样未命中。这就是 L2 与切图、调度的耦合点。

## 8.2 Cache 感知的分配代价

问题三把命中折算进 S2 的代理 $F$：核心 $k$ 的 `PIPE_MTE2` 占用由 $B^{\mathrm{in}}_k/\mathrm{bw}$ 改为

$$\frac{B^{\mathrm{in}}_k-H_k}{\mathrm{bw}}+\frac{H_k}{\mathrm{bw}_{\mathrm{L2}}}$$ {#8-4}

全局 DDR 下界由 $B_{\mathrm{DDR}}/\mathrm{bw}$ 变为 $(B_{\mathrm{DDR}}-\sum_kH_k)/\mathrm{bw}$。其中 $H_k$ 为核心 $k$ 的预测命中字节：对每个要从 DDR 读入多个核心的张量（图输入张量或跨核中间张量），第一个读入核按未命中计，其余读入核按命中计，大于 $C_{\mathrm{L2}}$ 的张量不计。这一改动带来一个定性变化：在问题二中，把一个被多核读取的张量复制到多个核心是纯粹的损失；在问题三中，第二份起只花约四分之一的时间且不占 DDR 带宽。重复读取的代价下降后，分核可以更多地追求负载均衡与并行。

代理没有模拟 FIFO 的淘汰与式（8-3）的时序条件，因此它对命中是乐观估计。为弥补这一点，S4 由官方问题三评估器择优，并把问题二的冠军方案放进问题三的候选池（跨问题互投）。最终 400 个问题三方案中有 {{ORIG_P3_cross}} 个来自问题二的候选，其余来自问题三自身的网格、单算子子图、采样与其他阶段的方案。

## 8.3 L2 容量与带宽的影响

**模型推断。** 由式（8-2），L2 带宽决定单次命中的收益系数 $1/\mathrm{bw}-1/\mathrm{bw}_{\mathrm{L2}}$。$\mathrm{bw}_{\mathrm{L2}}\to\infty$ 时系数趋于 $1/\mathrm{bw}$，题设 250 B/cycle 已取得这一上限的 76%；把带宽降到 125 B/cycle 只剩 52%；降到与 DDR 相同的 60 B/cycle 时单次命中不再更快，只剩"不占 DDR 带宽池"的收益。带宽越高，边际收益越小。容量则通过式（8-3）的第一个条件起作用：它决定一个被多核复读的张量能否在全部读者读完前留在 Cache 中。容量越小，要求各读者在时间上越集中，调度对命中率的影响越大；容量足够大时，第一个条件自动满足，命中只受第二个条件和 $\mathrm{value}(t)$ 的限制。

**命中与未命中的来源。** 我们用官方评估器重跑问题三的全部冠军方案，读取 Cache 事件流并按张量分类（图 8-3），逐项求和与官方命中、未命中字节完全一致。$N=4$ 时，{{L2S_hit_input_reuse}} 的命中字节来自图输入张量的重复读入，跨核中间张量占 {{L2S_hit_cross_core_mid}}。未命中字节中，{{L2S_miss_first_miss}} 是每个张量的首次读入（冷启动，不可避免），{{L2S_miss_concurrent_first_read}} 是多个核心在首次读入完成前并发读同一张量，{{L2S_miss_fifo_evicted}} 是写入后被 FIFO 淘汰、之后再读。后两类正对应式（8-3）的两个条件，占未命中的六成左右，是 Cache 感知调度可以争取的空间；本文的代理没有建模它们（第 10.2 节）。

**问题三与问题二的比较。** 任何问题二的方案都是问题三的可行方案，保底池又做了跨问题互投，所以问题三的冠军理应不慢于问题二。$N=4$ 时，问题三冠军在 {{P2P3_HI}} 个用例上快于问题二冠军，{{P2P3_EQ}} 个相等，{{P2P3_LO}} 个更慢（图 8-4）。在全部 400 个 (用例, $N$) 中，有 {{COND4_COUNT}} 个例外（括号内为问题三与问题二冠军的 Makespan，单位 cycle）：{{COND4_LIST}}，最大相对差 {{COND4_MAXREL}}。我们用两个评估器直接复核了同一方案，确认这不是互投或本项目代码的问题，而是 FIFO Cache 本身的时序效应：命中让部分 `COPY_IN` 提前完成，改变了后续搬运的相对完成顺序与 DDR 带宽的分配时序，关键路径上的个别操作因此略晚完成。这与列表调度中"资源变多反而变慢"的时序异常同类[@graham]。
