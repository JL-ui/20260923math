# 一、问题重述

## 1.1 问题背景

单核 NPU 的算力受制造成本、功耗与散热的限制，多核 NPU 因此成为主流形态[@liao]。赛题中的多核 NPU 由 $N$ 个同构 AI 核心和共享片外主存 DDR 组成。每个核心有 Cube 矩阵单元（`PIPE_M`）、Vector 向量单元（`PIPE_V`）、两类搬运单元（`PIPE_MTE2`：DDR→L1/UB 与 UB→L1；`PIPE_MTE3`：L1/UB→DDR 与 L1→UB），以及私有缓存 L1（524 288 B）和 UB（131 072 B）。所有核心读写 DDR 时共享 60 B/cycle 的总带宽。问题三另加全部核心共享的只读 L2 Cache（1 048 576 B，250 B/cycle，带宽独立于 DDR）。硬件结构见图 1-1。

![图 1-1　多核 NPU 硬件结构与本题固定配置](@@FIG@@/fig01_architecture.png){width=88%}

待调度对象是有向无环计算图 $G=(V,E)$，$V=T\cup O$ 为张量节点与操作节点，边只允许"张量→操作"或"操作→张量"。张量带 `pos`（DDR/L1/UB）与 `size`；操作带 `op`、`pipe`、`cycles`。图的输入、输出张量位于 DDR，中间张量位于核内缓存。

## 1.2 需要解决的问题

一个多核方案要同时确定三件事：每个非 `COPY_IN`/`COPY_OUT` 操作属于哪个子图（切图）；每个子图放在哪个核心（分核）；每个核心上子图的执行顺序（同核排序）。评估程序据此按场景规则重建跨子图搬运，用固定的核内调度算法（Step1–Step3）确定 Task 内的算子顺序与换入换出，再在共享带宽下模拟多核并行执行，输出 Makespan（主指标）、总额外数据搬运量（次指标）和 Cache 命中率（问题三）。

**问题一（场景 A）**：每个子图单独构成一个 Task，所有跨子图数据都经 DDR 中转；同核 Task 切换等待 100 cycle，跨核前驱等待 1000 cycle。要求给出 1～5 核平均加速比折线图、逐用例 Makespan 与总额外搬运量，并在 2～5 核范围内稳定、高效地求解（赛题说明"高效"指避免暴力迭代搜索，以单个用例 5～10 分钟内给出结果为佳）。

**问题二（场景 B）**：同一核心的全部子图合成一个 Task，同核子图直接复用 L1/UB 中的数据；跨核依赖经 `COPY_OUT`、500 cycle 同步延迟和 `COPY_IN` 完成。要求在严格满足 L1/UB 容量约束的前提下进一步缩短 Makespan、减少额外搬运，输出内容与问题一相同。

**问题三（共享只读 L2）**：在场景 B 上加入共享只读 L2，研究其容量与带宽对切图与调度的影响，建立模型与算法；给出 1～5 核下无 L2 与只读 Cache 两种配置的对比曲线，以及同核数下只读 Cache 相对无 L2 的加速比（无 L2 的 Makespan 除以只读 Cache 的 Makespan），并逐用例列出两种配置的 Makespan、额外搬运量与命中率。

**加速比口径**。单核基准 Makespan 由核内调度算法在整图上计算，单核加速比为 1；$k$ 核加速比为 $\mathrm{SU}_k=\mathrm{MK}_1/\mathrm{MK}_k$。平均加速比取全部用例加速比的算术平均，而不是总时间之比。由于核内调度是启发式的，单核基准本身不是最优，所以可能出现加速比大于核数的情况（第 5.5 节给出机理）。

# 二、问题分析

## 2.1 决策耦合与计算复杂性

切图、分核、排序三项决策互相牵制。切得越碎，并行机会越多，但跨子图边界越多，重复读取与 DDR 搬运随之增加；切得越粗，通信越少，却压缩了并行空间，还会让单个 Task 超出 L1/UB 容量而触发换入换出。分核决定负载是否均衡、多少依赖变成跨核依赖；同核顺序又影响依赖等待、张量驻留时长与换入换出量。

这类问题属于带通信代价的 DAG 调度。即使不考虑通信，把独立任务分到 $N$ 台同构机器使 makespan 最小就已是 NP-难问题（见命题 2-1），加入优先约束后即使任务等长也是 NP-完全的[@ullman]；带通信代价的 DAG 调度更是一个启发式方法林立的领域[@kwok]。本题还叠加了片上容量、流水线发射顺序和共享带宽争用。下面的命题说明，哪怕只留下最简单的特例，精确求解也不可行。

> **命题 2-1**　把问题限制为"$N=2$、算子级 DAG 无边、所有算子在同一条 Pipe、无容量与带宽约束、通信代价为零"，其判定版本仍是 NP-完全的。
>
> *证明*　任给 PARTITION 实例 $\{a_1,\dots,a_n\}$（PARTITION 是 NP-完全的[@karp]），构造含 $n$ 个孤立算子的计算图，令算子 $v_i$ 的周期 $c_{v_i}=a_i$。任一方案的 Makespan 为 $\max(L_0,L_1)$，$L_k$ 为核 $k$ 上的周期和，且 $L_0+L_1=\sum_i a_i$。于是存在 Makespan $\le\frac12\sum_i a_i$ 的方案当且仅当原实例可二等分。归约是多项式的，方案的可行性与 Makespan 也能在多项式时间内验证，故判定版本 NP-完全。$\square$

因此本文不追求精确解，目标是在"单用例求解时间远小于官方评估时间"的预算内稳定逼近第 5.5 节给出的下界。

与本题相关的研究大致有三类。第一类是图与超图划分：多层划分方法[@karypis]以割边为目标，超图划分的连通度 $(\lambda-1)$ 目标能准确刻画"一份数据被多方读取"的通信量[@catalyurek]，有向无环划分进一步要求划分后的商图无环[@herrmann]。第二类是深度学习计算图在多设备上的切分与放置，例如用强化学习学习放置策略[@mirhoseini]、在更大的并行策略空间中搜索[@jia]、分层自动化算子间与算子内并行[@alpa]，以及面向多核加速器的粗粒度数据流调度[@tangram]。这些方法的代价模型多以通信量或实测为依据。本题的评估器有两处它们通常不考虑的机制：核内启发式调度对片上张量的全局申请序，以及只读 FIFO 的共享 L2。本文的做法是先从评估器中读出这些机制，再据此确定模型的结构，第三类相关工作（BSP 框架下的 DAG 调度）在第 5.6 节讨论。

## 2.2 评估器的五条实现事实

所有指标都由官方程序给出，所以本文先逐行解析了 `code/` 下的评估脚本。其中五条事实直接决定了模型的形态。

**事实 1（边界重建规则）**。可切分节点恰为非 COPY 算子。评估器丢弃原图的 COPY 节点，再按场景规则重建边界搬运：场景 A 对每个子图的输入、输出边界张量各插一次 COPY；场景 B 只对图输入、图输出和跨核边插 COPY。推论：**场景 B 中同核子图之间的边界不产生任何搬运，切图在核内只起决定执行顺序的作用**。

**事实 2（核内执行序由子图顺序决定）**。场景 B 中核内算子序等于"按子图名次分桶、桶内保持 Step1 顺序"的稳定排序，所以同核子图顺序不仅决定依赖等待，也直接决定核内算子的物理执行序。

**事实 3（全局申请序）**。Step3 的发射逻辑把所有"会申请片上张量"的算子排进一个全局申请序，只有队首者可以发射（摘自 `code/schedule_step3.py`，有删节）：

```python
candidate = allocation_order[next_allocation_rank]
if candidate in allocation_ready and candidate_pipe == pipe and can_allocate_outputs(candidate):
    op_id = candidate          # 只有队首能发射
```

不申请片上张量的算子不受此限，但绝大多数算子都要申请片上输出张量，于是排在核内序列前部、数据尚未送达的跨核 `COPY_IN` 会让整个核心的四条 Pipe 几乎一起停下。项目早期对 case_062、$N=4$ 的一个方案做过诊断：某核心出现两段各约 $7.1\times10^5$ cycle 的空转，而配置中的跨核延迟只有 500 cycle（诊断记录见项目文档《评估器机制说明》）。这说明只把通信量降下来并不够，还必须把跨核依赖在时间上往后放。

**事实 4（换出规则）**。Step2 在容量超限时换出"下一次使用最远"的驻留张量（`schedule_step2.py` 中 `trigger_one_spill` 按 `next_use` 降序取首个），即 Belady 规则[@belady]。给定核内顺序后换出选择已近似最优，换入换出量主要由核内顺序与子图边界决定。

**事实 5（Cache 命中在发射时判定、写入在完成时发生）**。问题三中 `COPY_IN` 是否命中，在它发射时按当时的 FIFO 内容判定，条目要到搬运完成后才写入，命中也不刷新 FIFO 顺序。因此多个核并发首读同一张量会全部未命中；命中比未命中快且不占 DDR 带宽池，会改变各 `COPY_IN` 的完成先后，进而改变后续的淘汰顺序。所以**同一方案在问题三下的 Makespan 并不保证不高于它在问题二下的值**，第 8.4 节报告了这种情形在最终结果中的出现次数。

# 三、模型假设

1. **评估器即真值**。模型推断与官方评估器冲突时一律以评估器为准；上报指标全部由官方脚本在 `data/config.txt` 固定配置下给出。
2. **核内调度固定**。Step1–Step3 是给定的确定性过程，本文只通过子图划分与顺序间接影响它。
3. **核心同构**。$N$ 个核心的计算能力与私有缓存容量相同。
4. **DDR 公平共享**。$n$ 个在途 DDR 搬运各得 $1/n$ 带宽，与多核评估器的带宽池一致。
5. **Pipe 独占**。每核每条 Pipe 同时只有一条在飞指令，四条 Pipe 之间可以并行。
6. **只读 L2**。仅 `COPY_IN` 可以命中；键为写入片上的逻辑张量 id；FIFO 淘汰，命中不刷新顺序；大于容量的张量不缓存；L2 与 DDR 带宽池独立。
7. **搬运时长**。一次搬运的参考时长为字节数除以有效带宽（命中 250 B/cycle，未命中 60 B/cycle，再经带宽池公平共享重算）。
8. **求解预算**。单用例单候选的求解时间应远小于一次官方评估，算法不对"切图 × 分核 × 排序"做穷举。
