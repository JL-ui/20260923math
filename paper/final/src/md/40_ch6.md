# 六、问题一：场景 A 的模型与求解

## 6.1 Task 级时序模型

场景 A 中一个子图就是一个 Task。同核 Task 严格串行，一个 Task 在其全部前驱 Task 完成且等待期满后才能激活。评估器 `evaluate_scene_a` 中的释放时刻为：同核上一个 Task 结束后再等 $W_{\mathrm{same}}=100$ cycle，跨核前驱结束后再等 $W_{\mathrm{cross}}=1000$ cycle。记子图 $s$ 的开始、结束时刻为 $\mathrm{start}(s)$、$\mathrm{end}(s)$，$\mathrm{prevEnd}(y_s)$ 为核心 $y_s$ 上前一个 Task 的结束时刻，则

$$\mathrm{start}(s)=\max\Bigl\{\mathrm{prevEnd}(y_s)+W_{\mathrm{same}},\ \max_{s'\in\mathrm{pred}(s),\,y_{s'}\neq y_s}\bigl(\mathrm{end}(s')+W_{\mathrm{cross}}\bigr)\Bigr\}$$ {#6-1}

$$\mathrm{end}(s)=\mathrm{start}(s)+\mathrm{dur}(s),\qquad \mathrm{MK}^{\mathrm A}=\max_s\mathrm{end}(s)$$ {#6-2}

同核前驱由核内顺序 (C3) 自动先完成，所以式（6-1）不再单列。Task 内部由核内 Step1–3 调度，时长无闭式；搜索中用四条流水线的并行上界近似，两类 COPY 共用 DDR 带宽：

$$\mathrm{dur}(s)\approx\max\Bigl(M_s,\ V_s,\ \frac{B^{\mathrm{in}}_s+B^{\mathrm{out}}_s}{\mathrm{bw}}\Bigr)$$ {#6-3}

其中 $M_s=\sum_{v\in s,\,p_v=\mathrm M}c_v$，$V_s$ 同理。场景 A 在每条子图边界都重建 COPY（第 2.2 节事实 1），边界字节为

$$B^{\mathrm{in}}_s=\sum_{t:\ C_t\cap s\neq\varnothing,\ P_t\cap s=\varnothing}s_t,\qquad B^{\mathrm{out}}_s=\sum_{t:\ P_t\cap s\neq\varnothing,\ (t\in T_{\mathrm{out}}\ \vee\ C_t\not\subseteq s)}s_t$$ {#6-4}

式（6-4）逐条对应评估器的插入规则，没有拟合参数。我们在 {{TRAFFIC_CASES}} 个用例、三个问题共 {{TRAFFIC_N}} 组对照上把它与官方输出的新增搬运量比较，最大相对误差为 {{TRAFFIC_MAXERR}}（`solution/check_traffic_model.py`）。式（6-1）～（6-3）则是代理：它忽略了 Task 内部的换入换出和 DDR 争用，只用于搜索内部排序，所有上报数字仍取官方评估。

## 6.2 切图粒度的权衡

把某核心上的算子切成 $q$ 个子图，该核的完成时间近似为

$$T_k(q)\approx\max(M_k,V_k)+(q-1)\,W_{\mathrm{same}}+\frac{\Delta B(q)}{\mathrm{bw}}-\Phi(q)$$ {#6-5}

第一项与 $q$ 无关；第二项是 Task 切换开销；第三项是新增的边界搬运，$\Delta B(q)$ 随 $q$ 单调不减；第四项 $\Phi(q)$ 是子图变小后 Step2 换入换出的减少量，同样随 $q$ 单调不减。$q$ 太小时换入换出多，$q$ 太大时边界搬运和切换开销多，中间存在最优粒度 $q^{\ast}$。同核 Task 之间没有流水线重叠，把若干独立子图合成一个 Task，既能让头部 `COPY_IN` 与尾部 `COPY_OUT` 被计算掩盖，也免去了子图之间经 DDR 的往返，所以问题一的最优粒度偏粗。实验与此一致：最终方案的子图数中位数为 {{NSUB_MED_P1}}，远少于问题二的 {{NSUB_MED_P2}}；在 {{GRAN_N}} 个用例、$N=4$ 的粒度扫描中，问题一在块上限系数 $\beta={{GRAN_BEST_P1}}$ 处最好，$\beta=0.03$ 时损失 {{GRAN_LOSS_P1_0.03}}（第 9.4 节）。$q^{\ast}$ 依赖图结构，本文不解析求解，而是在 S4 用候选网格覆盖不同粒度，由官方评估器择优。

## 6.3 CAP-LS 算法

算法取名 CAP-LS（Communication-Aware Partitioning with Level Stratification），整体框架见图 6-1。三个问题共用这一流程，场景差异只落在代价权重、候选集合与 L2 折算三处。

![图 6-1　CAP-LS 求解框架](@@FIG@@/framework.png){width=100%}

**S1　亲和原子化与无环切块。** 以张量扇出区分两类连接：若 $|C_t|\le\theta$，称张量 $t$ 为强连接，把 $P_t\cup C_t$ 并入同一原子；若 $|C_t|>\theta$，称其为广播连接，允许被多个原子重复读取，不做绑定。$\theta$ 在 $\{\infty,16,8,4,2,1\}$ 中从大到小取第一个使"最大原子计算量不超过 $\beta W/N$"的值，其中 $W=\sum_v c_v$，$\beta$ 为粒度参数。收缩后的原子图可能有环，用 Tarjan 算法[@tarjan]求强连通分量并合并，得到原子级 DAG。按原子拓扑序拼接，原子内部采用与官方 Step1 同类的逆向 DFS 序，得到全局线性扩展 $\sigma$；计算量仍超过上限的原子沿 $\sigma$ 切成等负载的连续段。每个块都是 $\sigma$ 的连续区间，所以块级商图必然无环。

**S2　负载、通信与同步深度联合分配。** 初始分配有三种：最大优先（LPT）装箱[@graham]、沿 $\sigma$ 轮转、沿 $\sigma$ 连续等分。LPT 装入块 $b$ 时核心 $k$ 的代价为

$$\Delta(k)=\max\bigl(L^{\mathrm M}_k+M_b,\ L^{\mathrm V}_k+V_b\bigr)+w_{\mathrm{comm}}\sum_{j:\,c_j\neq k}\mathrm{bytes}(b,j)$$ {#6-6}

$\max(\cdot)$ 项分别累计 Cube 与 Vector 负载，让两类计算在同一核上互补。随后做移动式局部搜索：每次把一个块移到另一个核心，若代理目标 $F$（式（5-5））下降则接受（首次改进）。问题一中 $F$ 的同步项权重取 $W_{\mathrm{cross}}=1000$。为控制规模，只考察计算量最大的 260 个块，移动次数上限为 $\min(\max(300,8m'),2200)$（$m'$ 为考察块数），至多 6 轮。一次移动只重算该块触及张量的搬运贡献和块级同步深度，代价为 $O(|T_b|+m+e_B)$，$|T_b|$ 为块 $b$ 触及的张量数，$m$、$e_B$ 为块数与块间边数。

**S3　同步层次分层。** 由块的分配得到 $c(v)$，按定义 5-1 一次拓扑扫描算出 $r(v)$，取子图为 (核心, 层次) 等价类。候选中还可以换用推论 5-3 允许的另两种单调层指派：ALAP 填充（把算子在合法区间内后移到本核负载最轻的层）和层压缩（把过薄的层并入前一层）；也可以限定"每个子图至多 max_ops 个算子"，沿 $\sigma$ 再切片，对应第 6.2 节的粒度 $q$。由引理 5-1 与推论 5-3，所得方案自动满足 (C1)–(C5)。

**S4　多起点组合与保底池。** S1–S3 的结果取决于粒度 $\beta$、初始分配、子图成形方式与层指派。问题一使用 14 组候选（表 6-1 的 c0～c13），问题二、三再加 4 组单算子子图候选（c14～c17，第 7.2 节），共 18 组；候选全部交官方评估器打分。候选之间常产生相同方案，配合方案哈希缓存，同一方案只评估一次。

Table: 表 6-1　S4 的候选参数网格

| 编号 | 候选设置 | 设计意图 |
|:--|:--|:--|

## 6.4 "高效"的实现

赛题要求问题一的算法"高效"。在本题中，算法本身很快，耗时主要花在官方评估上：问题一评估器单次调用的最长耗时达到 {{EVAL_MAX}} s，而单候选 S1–S3 的算法时间中位数只有 {{RT_MED}} s（{{RT_N}} 次构造）。所以"高效"主要靠少调用评估器。我们采取了四项措施。

（1）**搜索内层只用解析代价。** 局部搜索中的 $F$ 可增量更新，不调用评估器；可行性由构造保证，搜索中不判环。

（2）**方案哈希缓存。** 评估结果按方案的规范化哈希写入磁盘缓存，不同候选、不同实验阶段产生的相同方案只评估一次。整个项目在固定配置下去重后共 {{TOTAL_EVALS}} 次官方评估。

（3）**按规模裁剪候选。** 问题一中 $|V_{\mathrm{op}}|\le6000$ 的 {{N_SMALL6K}} 个用例评估全部 14 组候选；$6000<|V_{\mathrm{op}}|\le12000$ 的 {{N_MID6K}} 个用例只评估前 8 组；$|V_{\mathrm{op}}|>12000$ 的 {{N_BIG12K}} 个用例只评估前 4 组。

（4）**大图代理兜底。** 对官方问题一评估的中位耗时超过 600 s 的用例（case_014、case_072、case_076、case_091），即使只评估 4 组候选也会远超 10 分钟。这 4 个用例跳过全部候选的官方评估，改用局部搜索结束时的解析代价 $F$ 排序，只把第一名交官方评估一次；随后的退火也只评估代理第一名。它们的上报成绩仍来自这一次官方评估，但候选之间的选择依据变成了代理，代价是可能选不到官方意义上的最好候选。这一代价的量级可以参考第 9.7 节的实验：在全部 100 个用例上改用 Task 级代理（式（6-1）～（6-3））在网格候选中选择，问题一 $N=4$ 的平均加速比由官方择优的 {{PSEL_P1_OFF}} 降到 {{PSEL_P1_PROXY}}（{{PSEL_P1_REL}}），{{PSEL_P1_LOSSN}} 个用例变差。兜底实际使用的是 $F$ 而非 Task 级代理，这一数字只作量级参考。就这 4 个用例本身而言，最终方案 $N=4$ 的加速比为 {{BIG4_SUMIN_N4}}～{{BIG4_SUMAX_N4}}，已接近线性，兜底造成的损失上限较小；它们的最终方案经保底池与其他阶段的官方评估结果比较后选出。

**代理驱动的模拟退火。** 层次构造偏保守：它把 Task 边界固定在层与层之间。为了在问题一中进一步调整 Task 的粗细，我们从网格冠军出发做模拟退火[@kirkpatrick]。适应度是式（6-1）～（6-3）的 Task 级代理，用增量状态维护，单步代价与图规模无关。邻域有三种：合并同核相邻的两个 Task（二者之间不存在经其他 Task 的路径时才允许）、把一个 Task 按拓扑序对半拆开、把一个 Task 移到另一个核心并按拓扑位置插入。退火会打破层次结构，所以每一步都检查 Task 图（依赖边与同核顺序边之并）是否无环，不可行的移动直接撤销。初温取初始代理值的 2%，按几何速率在 1500 步内降到初温的 $10^{-3}$；记录代理最好的 3 个不同方案交官方评估（大图只评估 1 个）。全部 400 个问题一配置中，退火耗时中位数为 {{SA_MED}} s，最长 {{SA_MAX}} s，超过 60 s 的有 {{SA_OVER60}} 个配置，分布在 {{SA_OVER60_CASES}} 个用例上，其中 {{SA_OVER60_N23}} 个配置的核数为 2 或 3（核数少时每个 Task 更大，拆分与合并的增量更新更贵）；退火方案在主实验阶段的 {{SA_CHAMP_MAIN}} 个配置上胜过全部网格候选，经保底池汇总后仍有 {{ORIG_P1_anneal}} 个最终方案来自退火。

## 6.5 复杂度分析

设 $n=|V_{\mathrm{op}}|$，$e=|E_{\mathrm{op}}|$，$\tau$ 为张量数，$m$ 为块数，$e_B$ 为块间边数，$B$ 为移动次数上限。各阶段的复杂度见表 6-2。

Table: 表 6-2　CAP-LS 各阶段复杂度（单候选）

| 阶段 | 复杂度 | 说明 |
|:--|:--|:--|
| 图解析与 COPY 收缩 | $O(n+e+\tau)$ | 一次性，结果缓存 |
| S1 亲和原子化 | $O((n+\tau)\,\alpha(n))$ | 并查集，至多 6 个 $\theta$ 值 |
| S1 SCC 合并与线性扩展 | $O(n+e)$ | 迭代 Tarjan、迭代逆向 DFS |
| S2 LPT 装箱 | $O(m\log m+mN)$ | |
| S2 局部搜索 | $O(B\,(\bar T+m+e_B))$ | $B\le2200$，$\bar T$ 为块平均触及张量数 |
| S3 层次分层与子图成形 | $O(n+e)$ | 一次拓扑扫描 |
| 合计 | $O(n+e+\tau+B\,(\bar T+m+e_B))$ | 对 $n$ 近似线性 |

整个流程不对"切图 × 分核 × 排序"做枚举：切图由 $\sigma$ 的连续区间构造，排序由引理 5-1 直接给出，只有分核进入搜索，而且搜索是增量的。作为对照，朴素枚举的规模为 $B_n\cdot N^{S}\cdot\prod_k|\pi_k|!$（$B_n$ 为 Bell 数），在最小的 {{FEAT_NOPS_MIN}} 个算子的用例上已无法计算。

几点观察。第一，平均加速比随核数稳定上升，$N=4$ 时为 {{SU_P1_N4}}，中位数 {{MED_P1_N4}} 明显高于均值，说明少数结构受限的难例拉低了平均值；$N=4$ 时加速比最低的是 {{WORST_P1N4}}，它们都属于"单一主分量"或长同步链结构（第 9.8 节）。第二，每个核数下的最小加速比都不低于 1，且逐用例随核数单调不降，这来自保底池的 $N-1$ 嵌入与单核兜底。第三，出现了超线性加速：$N=2$ 时 {{SUPER_P1_N2}} 个用例超过 2。按式（5-8），超线性来自单核基准自身的换入换出，而非多核"做得比理想还好"。第四，$N=4$ 时 100 个用例共新增 DDR 搬运 {{ADD_P1_N4}} 字节，其中切分边界占 {{ADDPART_P1}}，其余 {{ADDSPILL_P1}} 来自核内换入换出；场景 A 的每条子图边界都要经 DDR 往返，边界搬运的占比高于问题二（{{ADDPART_P2}}）。
