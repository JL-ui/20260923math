##* 附录B 性质的证明

**性质 1 的证明。** （C1）由构造直接成立：每个算子恰属于一个等价类 $S(k,\rho)$，每个子图恰出现在所在核心的 $\pi_k$ 中一次。对任意 $(u,v)\in E_{\mathrm{op}}$，若 $c(u)=c(v)$，由[@eq:level]得 $r(v)\ge r(u)$，两者同属一个等价类，或 $v$ 所在子图的编号更大；若 $c(u)\ne c(v)$，则 $r(v)\ge r(u)+1$，$v$ 所在子图的编号严格更大。所以 $E_S$ 的每条边都指向编号更大的子图，子图依赖图无环，（C2）成立；同核情形给出（C3）。（C4）新增的同核顺序边也沿编号递增，并集仍无环。（C5）中的核内依赖与流水线发射顺序都服从核内算子序，而按规则（2），核内算子序沿子图编号递增；跨核 COPY 边沿层次严格递增，所以并集中不存在回边。证毕。

**性质 2 的证明。** 若 $(u,v)$ 跨核且 $r(u)=r(v)=\rho$，由[@eq:level]得 $r(v)\ge\rho+1$，矛盾，故同一层次内不存在跨核依赖。性质 1 与上一句的证明只用到不等式 $r(v)\ge r(u)+\mathbb{1}[c(u)\ne c(v)]$，因此把 $r$ 换成任一单调层指派 $l$ 后结论不变。

再证逐点最小性。设 $l$ 为任一单调层指派，对算子按拓扑序归纳证明 $r(v)\le l(v)$。若 $v$ 无前驱，$r(v)=0\le l(v)$。否则由归纳假设，对每个前驱 $u$ 有 $r(u)\le l(u)$，于是

$$
r(v)=\max_{(u,v)\in E_{\mathrm{op}}}\bigl(r(u)+\mathbb{1}[c(u)\ne c(v)]\bigr)\le\max_{(u,v)\in E_{\mathrm{op}}}\bigl(l(u)+\mathbb{1}[c(u)\ne c(v)]\bigr)\le l(v)
$$

最后一步用到 $l$ 的单调性。又由[@eq:level]，$r$ 本身满足单调条件，所以 $r$ 是所有单调层指派中逐点最小的一个。证毕。

**问题 NP-难的说明。** 把问题限制为“$N=2$、算子级 DAG 无边、所有算子在同一条流水线、无容量与带宽约束、通信代价为零”。任给 PARTITION 实例 $\{a_1,\dots,a_n\}$[[karp]]，构造含 $n$ 个孤立算子的计算图，令 $c_{v_i}=a_i$。任一方案的 Makespan 为 $\max(L_0,L_1)$，其中 $L_k$ 为核 $k$ 上的周期之和，且 $L_0+L_1=\sum_i a_i$，于是存在 Makespan 不超过 $\frac{1}{2}\sum_i a_i$ 的方案，当且仅当原实例可以分成和相等的两部分。归约是多项式的，给定方案的可行性与 Makespan 可在多项式时间内验证，所以该受限问题的判定版本是 NP-完全的，原问题是 NP-难的。证毕。

##* 附录C 程序说明与复现步骤

**运行环境。** 程序用 Python 实现（3.10 及以上），在材料包根目录下运行，依赖见 requirements.txt。求解部分只用标准库；scipy 用于统计检验与代理检验，matplotlib 与 numpy 用于绘制实验结果图。评估程序与用例数据保持原样，配置文件未做修改。

: 程序与数据的目录结构 {#tbl:dirs widths=4.4,7.6}
| 路径 | 内容 |
|:---|:---|
| code/、data/ | 给定的评估程序、100 个用例与固定配置（只读） |
| solution/solve.py | 单用例求解入口，按标准求解流程输出方案文件 |
| solution/npu/ | 算法实现：读图与 COPY 收缩、S1 切块、S2 分配与局部搜索、S3 分层、表调度、问题一退火、搜索代理、评估程序封装与哈希缓存 |
| solution/run_experiments.py | 实验驱动：主实验、基线、消融、粒度与硬件灵敏度 |
| solution/run_all.sh | 按顺序运行全部实验阶段 |
| 方案文件/ | 与正文、附录 A 一一对应的 1500 个方案文件，按 p1～p3（问题）、n1～n5（核数）分目录存放 |

**输入与输出格式。** 输入为计算图文件 data/case_XXX.json；输出文件名为 case_XXX_multicore_res.json，顶层只有 node_to_subgraph 与 core_schedules 两个字段。子图编号按层次与核心的字典序递增分配，每个核的子图序列为其子图编号的升序，对应性质 1 的构造。

**单用例求解与评估。** 以问题二、4 核为例：

```bash
python solution/solve.py data/case_001.json --problem 2 --cores 4 -o out.json
python code/multicore_cut_evaluate_problem_2.py data/case_001.json out.json --config data/config.txt
```

问题一、三分别把 --problem 与评估脚本换成对应编号。solve.py 执行与正文相同的标准求解流程，包括两类兜底候选。

**复现全部实验。** 评估结果按方案哈希缓存，删除 results/cache 即从零重算；随机过程全部固定种子。

```bash
bash solution/run_all.sh 16
```

参数 16 为并行进程数。脚本依次计算单核基准，运行 $N=1$ 参考点、主实验、问题三两种配置的对比、基线、消融以及粒度与硬件参数灵敏度实验，结果写入 results/ 目录。
