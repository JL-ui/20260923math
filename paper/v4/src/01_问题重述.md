# 问题重述与问题背景 {#sec:ch1}

## 问题背景 {#sec:bg}

神经网络模型的参数量与计算量持续增长，单个 AI 核心受制造成本、功耗与散热的限制，难以独立满足算力需求，多核神经网络处理器（NPU）因而成为提升并行度与能效的常用架构[[ascend,davinci]]。在多核 NPU 上运行一个网络，编译器需要把计算图划分为若干子图，把子图分配到各个核心，并确定每个核心上子图的执行顺序。这一过程要在多核并行度、核内缓存容量与共享主存带宽之间权衡：子图切得过细，跨核数据搬运与同步增多；切得过粗，并行空间不足，单个核心还可能因片上缓存装不下而频繁换入换出。

所研究的多核 NPU 由 $N$ 个同构 AI 核心和共享片外主存 DDR 组成（[@fig:hardware]）。每个核心含 Cube 矩阵计算单元（PIPE_M）、Vector 向量计算单元（PIPE_V）和两类搬运单元：PIPE_MTE2 负责 DDR 到 L1/UB 以及 UB 到 L1 的搬运，PIPE_MTE3 负责 L1/UB 到 DDR 以及 L1 到 UB 的搬运。每个核心有私有的 L1（512 KB）与 UB（128 KB），四条流水线可以并行，每条流水线同一时刻只执行一条指令。所有核心公平共享 60 B/cycle 的 DDR 总带宽。问题三另在各核心与 DDR 之间加入一块所有核心共享的只读 L2 Cache，容量 1 MB，带宽 250 B/cycle，且与 DDR 带宽相互独立。

![多核 NPU 硬件结构与固定配置参数](figures/v4/fig_hardware.svg){#fig:hardware width=15.6}

待调度对象是一张有向无环计算图 $G=(V,E)$，其中 $V=T\cup O$，$T$ 为张量节点集，$O$ 为操作节点集，边只允许“张量→操作”或“操作→张量”。张量节点记录存储位置（DDR、L1 或 UB）与字节数，操作节点记录算子类型、所属流水线与执行周期数。图的输入、输出张量位于 DDR，中间张量位于核内存储，原图中的 COPY_IN、COPY_OUT 操作描述 DDR 与片上存储之间的数据搬运。以分块矩阵乘为例，每个数据块依次经历“COPY_IN 搬入、Cube 计算、COPY_OUT 写回”，整张计算图由大量这样的分块计算链交织而成。

与该问题相关的研究大致有三类。第一类是图与超图划分：多层划分以割边为目标[[metis]]，超图划分的连通度目标 $(\lambda-1)$ 能刻画“一份数据被多方读取”的通信量[[catalyurek,catalyurek23,mtkahypar]]，有向无环划分进一步要求商图无环[[herrmann]]。第二类是深度学习计算图在多设备或多核加速器上的切分、融合与调度，包括设备放置与并行策略搜索[[mirhoseini,jia,alpa,nnscaler]]、多核与多芯粒加速器上的层间流水与层融合调度[[tangram,set,gemini,stream,defines,tileflow]]、算子融合与跨算子的片上复用[[welder,hidet,souffle,chimera,mcfuser,korch]]，以及显存或片上存储受限的调度[[magis,memsched]]。第三类是带通信代价的 DAG 调度与整体同步并行（BSP）模型[[kwok,valiant,papp25,papp24,barrier26]]。这些方法的代价模型多以通信量、实测时间或性能模型为依据。本文所研究问题的评价由一个确定的评估程序给出，其中核内调度的全局申请序与只读 FIFO 共享 Cache 是通用模型通常不考虑的机制，需要先从评估程序中读出，再纳入模型。

## 问题重述 {#sec:restate}

针对上述平台，需要为给定计算图构造多核切图与调度方案。一个完整方案同时确定三类决策：

（1）**切图**：为每个非 COPY_IN、COPY_OUT 算子指定所属子图，把计算图划分为若干子图；

（2）**分核**：把每个子图分配到唯一的 AI 核心；

（3）**同核排序**：确定同一核心上各子图的执行顺序。

方案以两个字段提交：切图方案 node_to_subgraph 与子图调度方案 core_schedules。方案须覆盖全部核内算子，子图之间的依赖图无环，同核子图顺序不违反依赖。评估程序据此按场景规则重建跨子图的数据搬运，再用固定的核内调度流程处理每个 Task：Step1 按数据依赖确定拓扑次序，Step2 在片上容量不足时插入换入换出，Step3 按流水线资源排布算子发射；最后在共享带宽条件下模拟多核并行执行，输出总完成时间 Makespan（主指标）、总额外数据搬运量和 Cache 命中率（次指标）。

**问题一**：无核间同步机制（场景 A）下的多核切图与调度。一个 Task 只包含一个子图，同核 Task 串行执行，Task 之间不保留核内缓存数据，跨子图数据都经 DDR 中转；同核相邻 Task 之间有 100 cycle 的切换等待，依赖其他核心上前驱 Task 时，须等该前驱完成后再等待 1000 cycle。要求在 1～5 核下以缩短 Makespan 为主要目标、兼顾总额外搬运量，求解算法在 2～5 核范围内稳定、高效（单个用例 5～10 分钟内完成），给出平均加速比折线图，并逐用例列出 Makespan 与总额外搬运量。

**问题二**：有核间同步机制（场景 B）下的多核切图与调度。同一核心上的全部子图合并为一个 Task，同核子图可以直接复用 L1/UB 中的数据；跨核依赖由源核 COPY_OUT、500 cycle 同步延迟与目标核 COPY_IN 完成。要求在严格满足 L1/UB 容量约束的前提下进一步缩短 Makespan、减少额外搬运，输出内容与问题一相同。

**问题三**：共享只读 L2 Cache 条件下的多核切图与调度。在场景 B 的基础上加入共享只读 L2 Cache，研究其容量与带宽对切图与调度的影响并设计算法；给出 1～5 核下“无 L2”与“只读 Cache”两种配置的对比曲线，以及相同核数下只读 Cache 相对无 L2 的加速比，并逐用例列出两种配置的 Makespan、额外搬运量与命中率。

**加速比口径**。单核基准 Makespan 由核内调度流程在整图上计算，单核加速比记为 1；$N$ 核加速比为 $\mathrm{SU}_N=\mathrm{MK}_1/\mathrm{MK}_N$，平均加速比取 100 个用例加速比的算术平均。核内调度是启发式的，单核基准本身并非最优，因此加速比可能大于核数，其来源见[@sec:bound]。

## 问题分析 {#sec:analysis}

三个问题共享切图、分核、同核排序三项决策，三者相互牵制（[@fig:tradeoff]）。切图改变子图规模、并行空间与通信边界；分核决定负载分布和哪些依赖成为跨核依赖；同核顺序影响依赖等待、张量驻留时长与换入换出。细化切分能增加可独立调度的任务，也会引入更多子图边界与跨核传输；扩大子图有利于数据局部性，却压缩并行空间，并增加负载失衡与片上容量不足的风险。

![多核切图与调度中计算、通信与存储之间的权衡](figures/v4/fig_tradeoff.svg){#fig:tradeoff width=14}

即使去掉通信、容量与带宽，只把独立任务分到两个同构核心上使完成时间最短，该问题的判定版本已是 NP-完全的[[ullman,karp]]。100 个用例中最小的图有 @@FT_NOPS_MIN@@ 个可切分算子，最大的有 @@FT_NOPS_MAX@@ 个，对切图、分核、排序的组合空间做枚举并不可行，因此采用“构造可行解、局部搜索、评估程序择优”的启发式路线，并用理论下界衡量解的质量。三个问题的差异见[@tbl:diff]。

### 问题一的分析

场景 A 中子图就是 Task，同核 Task 严格串行、彼此不保留缓存数据，每一条子图边界都要经 DDR 往返一次，跨核依赖还要额外等待 1000 cycle。子图切得越细，边界搬运和 Task 切换越多；切得越粗，单个 Task 越可能超出 L1/UB 容量而触发换入换出，核间并行也越少。一个 Task 须等全部前驱 Task 完成才能激活，跨核依赖链的级数会逐级累加到 Makespan 上。仅用“负载均衡加少切边”的静态目标无法反映这种累加，所以问题一需要一个描述 Task 激活时刻与边界搬运的时序模型，用它比较不同粒度，并在构造出的方案上调整 Task 粗细。

### 问题二的分析

场景 B 把同一核心的子图合成一个 Task，同核子图边界不再产生搬运，子图边界不再必然是通信边界，决定通信的是核心边界：跨核搬运量主要由分核决定，切图的主要作用变为控制核内执行顺序。跨核依赖的名义延迟只有 500 cycle，但核内调度的全局申请序可能让一个数据尚未到达的跨核 COPY_IN 堵住整个核心（[@sec:rules]），因此依赖远端数据的算子不宜排在核内执行序的前部。同一 Task 内的子图共享 L1/UB，核内顺序决定同一时刻有哪些张量驻留在片上，顺序不当会引发大量换入换出。问题二可以概括为“分核决定通信、顺序决定驻留”，两者需要联合优化。

### 问题三的分析

问题三在场景 B 上增加共享只读 L2，需要先弄清命中从哪里来。评估程序的 Cache 只服务 COPY_IN，按 FIFO 淘汰，在发射时判定命中、在搬运完成时写入。由此可以推出，命中只可能来自同一张量被多个核心各自读入，或同一核心对同一张量的再次读入；命中字节的上界由计算图中可共享的重复读取量决定，能否达到则取决于各次读取之间的时间间隔。建模时可以把预测命中带来的时间收益纳入分配代价，但首次读取、并发首读以及被淘汰后的再次读取仍要访问 DDR。最后通过无 L2 与只读 Cache 两种配置的对比，以及对容量和带宽的扫描，说明 L2 的作用范围。

## 技术路线 {#sec:route}

技术路线见[@fig:roadmap]。第 2、3 章给出模型假设与符号。第 4 章分析评估程序中影响模型结构的规则，建立三个问题共用的优化模型，并用跨核同步层次构造满足结构约束的子图。第 5～7 章给出 CAP-LS（Communication-Aware Partitioning with Level Stratification）求解算法及其在三个问题上的调整，三者的差别集中在代价权重、候选集合与 L2 折算三处。第 8 章在 100 个用例上做基线对比、事后消融、灵敏度分析与代理可靠性检验，第 9 章评价模型。
