##* 附录B 程序说明与复现步骤

**运行环境。** 程序为纯 Python 实现，在赛题材料包根目录下运行，要求 Python 3.10 及以上；依赖见仓库根目录的 `requirements.txt`（numpy、scipy、matplotlib、python-docx）。CAP-LS 的求解部分只用标准库，scipy 只用于统计检验，matplotlib 与 python-docx 只用于作图和生成 Word。官方评估脚本 `code/` 与数据 `data/` 保持赛题原样，`data/config.txt` 未做任何修改。

: 程序与数据的目录结构 {#tbl:dirs widths=4.2,7.4}
| 路径 | 内容 |
|:---|:---|
| `code/`、`data/` | 赛题提供的评估程序、示例生成器、100 个用例与固定配置（只读） |
| `solution/solve.py` | 单用例求解入口，输出官方格式方案 |
| `solution/npu/` | 算法实现：读图与 COPY 收缩、S1 切块、S2 分配与局部搜索、S3 分层、表调度、问题一退火、事件模拟代理、官方评估封装与哈希缓存 |
| `solution/run_experiments.py` | 实验驱动：主实验、基线、消融、粒度、硬件灵敏度等阶段 |
| `solution/build_pool.py`、`export_plans.py`、`verify_final.py` | 保底池汇总；导出官方格式最终方案；用官方命令行脚本逐个复核 |
| `solution/paper_v2/` | 本文的数字提取（facts.py）、作图（figs_*.py、trace_fig.py）与 Word 排版（build_docx.py） |
| `results/` | 全部实验记录（csv、json）、评估缓存与最终方案 |

**输入与输出格式。** 输入为赛题附录 B.3 格式的计算图 `data/<case>.json`；输出严格按赛题附录 B.5，文件名为 `<case>_multicore_res.json`，顶层只有 `node_to_subgraph` 与 `core_schedules` 两个字段。CAP-LS 生成的子图编号按 (层, 核) 递增分配，每个核的内层数组就是其子图编号的升序，这一性质保证了引理 4-1 的可行性。

**单用例求解与官方评估。**

```bash
# 生成问题 2、4 核的方案（候选网格逐个交官方评估器择优）
python solution/solve.py data/case_001.json --problem 2 --cores 4 -o out.json
# 用官方脚本评估（问题 1/2/3 分别换成对应脚本）
python code/multicore_cut_evaluate_problem_2.py data/case_001.json out.json \n       --config data/config.txt
```

`solve.py` 只包含候选网格，不含退火、采样和保底池，因此其结果可能略低于正文报告的最终方案（[@sec:weak]）；所有网格候选都失败时，它退回整图单核方案，保证总有可行输出。

**复现全部实验与本文。** 评估结果按方案哈希缓存在 `results/cache/p{1,2,3}/`，删除该目录即从零重算；随机过程全部固定种子，重复运行得到相同的 `final.csv`。

```bash
bash solution/run_all.sh 16                          # 主实验、基线、消融与灵敏度
python solution/build_pool.py --jobs 16              # 保底池汇总 -> final.csv
python solution/export_plans.py                      # 导出官方格式最终方案
python solution/verify_final.py --problems 1 2 3     # 官方命令行逐方案复核
python solution/paper_v2/facts.py                    # 提取正文数字
python solution/paper_v2/figs_diagrams.py            # 示意图与流程图
python solution/paper_v2/figs_data.py                # 数据图
python solution/paper_v2/trace_fig.py                # 官方 trace 甘特图
python solution/paper_v2/build_docx.py               # 生成本文的 Word 与 PDF
```

正文与附录中的实验数字均不手工填写：`facts.py` 从 `results/` 中的 csv 与 json 计算全部数字，Word 源文件中以占位符引用，`build_docx.py` 遇到未定义的占位符会直接报错。

##* 附录C 核心程序（节选）

**（1）跨核同步层次与子图成形**（`solution/npu/stratify.py`，对应定义 4-1 与引理 4-1）

```python
def cross_core_levels(g, core_of_op):
    """r(v)：沿依赖路径累计的换核次数（拓扑序一次扫描）。"""
    level = {}
    for v in g.topo:
        cv = core_of_op[v]
        best = 0
        for p in g.preds[v]:
            cand = level[p] + (1 if core_of_op[p] != cv else 0)
            best = max(best, cand)
        level[v] = best
    return level


def build_subgraphs(g, core_of_op, num_cores, rank, max_ops=None, levels=None):
    """子图 = (核心, 层次) 等价类，按 (层次, 核心, 切片序) 递增编号。"""
    levels = levels if levels is not None else cross_core_levels(g, core_of_op)
    check_monotone(g, core_of_op, levels)          # 显式层指派须满足推论 4-3 的单调性
    buckets = defaultdict(list)
    for v in g.nodes:
        buckets[(levels[v], core_of_op[v])].append(v)
    mapping, schedules, sid = {}, [[] for _ in range(num_cores)], 0
    for (r, k) in sorted(buckets):                 # 编号沿 (r, k) 递增 -> 商图无环
        members = sorted(buckets[(r, k)], key=lambda v: rank[v])
        step = max_ops or len(members)
        for i in range(0, len(members), step):     # 可选：按规模沿 sigma 切片
            for v in members[i:i + step]:
                mapping[v] = sid
            schedules[k].append(sid)
            sid += 1
    return mapping, schedules, levels
```

**（2）容量感知表调度的评分**（`solution/npu/listsched.py`，对应式（6-5）与算法 6-1）

```python
def upward_rank(g, core_of_op, delay, bandwidth):
    """rank_u(v) = c_v + max_s (comm(v,s) + rank_u(s))，归一化到 [0, 1]。"""
    pb, rank = pair_bytes(g), {}
    for v in reversed(g.topo):
        best = 0.0
        for s in g.succs[v]:
            same = core_of_op[s] == core_of_op[v]
            comm = 0.0 if same else delay + pb[v].get(s, 0) / bandwidth
            best = max(best, comm + rank[s])
        rank[v] = max(1, g.cycles(v)) + best
    top = max(rank.values(), default=1.0) or 1.0
    return {v: r / top for v, r in rank.items()}


def pick(k):                                       # 为核 k 选下一个算子
    pool = ready[k][:TOP_CANDIDATES]               # 秩最高的 64 个就绪算子
    latest = max(range(4), key=lambda p: (pipe_free[k][p], -p))
    best_feasible, best_fallback = None, None
    for _, v in pool:
        alloc, dl, c = delta_live(v, k)            # 驻留净变化 Δlive 与对应容量 C
        if best_fallback is None or (dl, v) < best_fallback[:2]:
            best_fallback = (dl, v)
        if any(used[k][pos] + alloc[pos] > limit[pos] for pos in ("L1", "UB")):
            continue                               # 超过 alpha*C 的候选不参与评分
        p = PIPE_INDEX[g.pipe(v)]
        score = (rank[v] - mu * dl / c + (nu if p != latest else 0.0)
                 + noise * gumbel.get(v, 0.0))       # 式（6-5）
        if best_feasible is None or (score, -v) > best_feasible[:2]:
            best_feasible = (score, -v, v)
    return best_feasible[2] if best_feasible else best_fallback[1]
```
