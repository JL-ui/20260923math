%% TITLE: 基于跨核同步层次分层的通用 NPU 多核切图与调度
%% KEYWORDS: 多核 NPU；计算图切分；无环划分；跨核同步层次；容量感知表调度；只读 L2 Cache；组合式局部搜索

::: abstract
多核 NPU 调度需要联合决定三件事：把算子–张量计算图切成哪些子图、每个子图放到哪个核心、各核心按什么顺序执行子图，目标是在数据依赖、L1/UB 容量、四条指令流水线和共享 DDR 带宽的约束下缩短总执行时间 Makespan，并控制额外数据搬运。本文把官方评估程序作为唯一的事实基准，按“机理分析—统一建模—算法设计—检验评价”的路线求解三个问题，文中全部 Makespan、搬运量与命中率均由官方评估脚本在固定配置 config.txt 下给出。

**机理分析与统一模型。** 逐行解析评估器后发现一条决定模型形态的隐含约束：核内调度对“申请片上张量的算子”施加全局申请序，只有队首者能发射，因此排在核内序列前部、数据尚未送达的跨核 COPY_IN 会让整个核心的四条流水线一起停摆，真实代价远大于配置中 500 或 1000 cycle 的名义延迟。据此，本文定义跨核同步层次 $r(v)$，以“子图 = (核心, 层次) 等价类”作为切图的构造性定义，证明按 $(r,c)$ 编号后赛题的全部硬约束自动成立，搜索中无需判环；官方 trace 的受控对比显示，仅按同步层次重组子图就使同一用例的整核停摆时间下降 @@TRACE_ST_DROP@@。在此之上设计三个问题共用的四阶段算法 CAP-LS：S1 以张量扇出阈值做亲和原子化并按线性扩展连续分块；S2 以 Cube/Vector 负载、DDR 字节与同步深度的复合代价做分核与增量局部搜索；S3 做同步层次分层；S4 以 14～18 组多起点候选由官方评估器择优，并用保底池保证逐用例加速比随核数不降。

**针对问题一**（场景 A，子图即 Task），建立 Task 级时序模型，揭示“边界搬运随粒度增加、换入换出随粒度减少”的权衡，得出场景 A 偏粗粒度的结论，并加入代理驱动的模拟退火调整 Task 粗细。在全部 100 个用例上，$N=2\sim5$ 的平均加速比为 @@P1_MEAN_LIST@@；单个 (用例, 核数) 的端到端求解时间中位数为 @@P1_RT_MED@@ s，@@P1_RT_LE10@@/400 个配置在 10 分钟内完成。

**针对问题二**（场景 B，核即 Task），证明跨核搬运量恰为以张量字节为权的 $(\lambda-1)$ 超图割，并把“驻留对顺序”的权衡建模为容量感知表调度，新增单算子子图候选。平均加速比为 @@P2_MEAN_LIST@@；冠军方案的换入换出总量下降 @@SPILL_DROP@@；$N=4$ 时 @@P2_SUPER_4@@ 个用例出现超线性加速，其来源是单核基准自身的大量换入换出在多核切分后消失。

**针对问题三**（场景 B + 共享只读 L2），由评估器的 FIFO 命中规则推出命中只来自多核复读与换入复读，给出命中上界与时序条件，把预测命中字节按 250 B/cycle 折算进分配代价，并让问题二、三的冠军方案互投。只读 Cache 配置在 $N=2\sim5$ 的平均加速比为 @@P3_MEAN_LIST@@；只读 Cache 相对无 L2 的平均加速比在 $N=1\sim5$ 时为 @@L2G_LIST@@，按字节命中率 @@HIT_RANGE@@。机理分析与灵敏度实验表明，题设的 1 MB、250 B/cycle 已接近饱和，收益上限由计算图可共享的复读量决定，而约 @@MISS_AVOID_N4@@ 的未命中来自并发首读与 FIFO 淘汰，是 Cache 感知调度可继续争取的空间。

**模型检验。** 与随机、拓扑等分、负载均衡、通信聚类四类基线相比，$N=4$ 时三个问题的平均加速比分别比最强基线高 @@VSB4_P1_REL@@、@@VSB4_P2_REL@@、@@VSB4_P3_REL@@（Wilcoxon 符号秩检验，Holm 校正 $p\le @@VSB4_P2_P@@$），且没有一个用例劣于该基线；消融实验表明同步层次分层是贡献最大的单一机制，去掉后三个问题的平均加速比分别变化 @@ABL_P1_NO_LEVEL@@、@@ABL_P2_NO_LEVEL@@、@@ABL_P3_NO_LEVEL@@，与通信感知分块同时去掉则达 @@ABL_P1_NO_LEVEL_NO_COMM@@、@@ABL_P2_NO_LEVEL_NO_COMM@@、@@ABL_P3_NO_LEVEL_NO_COMM@@。全部 @@VERIFY_N@@ 个最终方案经官方命令行脚本逐一复核，不一致数为 @@VERIFY_MISMATCH@@。

本文的创新点在于：（1）从评估器中识别出“全局申请序导致整核停摆”的机制，并据此提出跨核同步层次分层；（2）把可行性写成构造性定理，使搜索只在分核这一维上进行；（3）用一套框架覆盖三个场景，场景差异只落在代价权重、候选集合与 L2 折算三处。
