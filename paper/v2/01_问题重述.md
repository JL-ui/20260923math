# 问题背景与问题重述 {#sec:ch1}

## 问题背景 {#sec:bg}

随着人工智能模型规模持续增长，单个 AI 核心受制造成本、功耗与散热的约束，难以独立满足算力需求，多核 NPU 因此成为提升并行能力与能效的主流架构[[1]]。在多核 NPU 上运行一个神经网络，编译器需要把完整的计算图划分为若干子图、把子图分配到各个核心，并确定每个核心上子图的执行顺序。这一过程既要利用核内高效的计算单元与私有缓存复用数据，又要协调跨核依赖，本质上是在多核并行度、核内缓存容量与共享主存带宽三者之间做权衡：切得太碎，跨核数据搬运与同步增多；切得太粗，并行空间不足，单个核心还可能因缓存装不下而频繁换入换出。

赛题给出的多核 NPU 由 $N$ 个同构 AI 核心和共享片外主存 DDR 组成，硬件结构与本题的固定参数如[@fig:hardware]所示。每个核心有 Cube 矩阵单元（`PIPE_M`）、Vector 向量单元（`PIPE_V`）和两类搬运单元（`PIPE_MTE2` 负责 DDR→L1/UB 与 UB→L1，`PIPE_MTE3` 负责 L1/UB→DDR 与 L1→UB），以及私有缓存 L1（512 KB）和 UB（128 KB）。四条流水线可以并行，但每条流水线同一时刻只执行一条指令。所有核心读写 DDR 时公平共享 60 B/cycle 的总带宽；问题三另加一个所有核心共享、带宽独立于 DDR 的只读 L2 Cache（1 MB，250 B/cycle）。

![多核 NPU 硬件结构与本题固定配置](figures/v2/fig_hardware.png){#fig:hardware width=15}

待调度对象是一张有向无环计算图 $G=(V,E)$，$V=T\cup O$ 由张量节点和操作节点组成，边只允许“张量→操作”或“操作→张量”。张量带有存储位置 `pos`（DDR/L1/UB）与字节数 `size`；操作带有类型 `op`、所在流水线 `pipe` 与周期数 `cycles`。图的输入、输出张量位于 DDR，中间张量位于核内缓存。以分块矩阵乘为例，每个数据块依次经历“COPY_IN 搬入—Cube 计算—COPY_OUT 写回”，计算图正是由大量这样的分块计算链交织而成。

与本题相关的研究大致有三类。第一类是图与超图划分：多层划分方法[[5]]以割边为目标，超图划分的连通度 $(\lambda-1)$ 目标能够准确刻画“一份数据被多方读取”的通信量[[6]]，有向无环划分进一步要求划分后的商图无环[[7]]。第二类是深度学习计算图在多设备上的切分与放置，例如用强化学习学习放置策略[[8]]、在更大的并行策略空间中搜索[[9]]、分层自动化算子间与算子内并行[[10]]，以及面向多核加速器的粗粒度数据流调度[[11]]。第三类是带通信代价的 DAG 调度与整体同步并行（BSP）模型[[3,13,14]]。这些方法的代价模型多以通信量或实测时间为依据，而本题的成绩完全由一个确定的评估程序给出，其中核内启发式调度的“全局申请序”与只读 FIFO 共享 Cache 是通用模型通常不考虑的机制。本文的出发点正是先把这些机制从评估器中读出来，再据此确定模型的结构。

## 问题重述 {#sec:restate}

一个多核调度方案需要同时给出两部分内容：一是**切图方案** `node_to_subgraph`，为每个非 COPY_IN/COPY_OUT 的操作指定子图编号；二是**子图调度方案** `core_schedules`，为每个核心列出其上子图的执行顺序。方案须满足：映射覆盖全部核内操作，子图依赖图为有向无环图，同核子图顺序不违反依赖。评估程序据此按场景规则重建跨子图的数据搬运，用固定的核内调度算法（Step1 确定拓扑序、Step2 在容量不足时插入换入换出、Step3 在四条流水线上排布）确定每个 Task 内的算子顺序，再在共享带宽下模拟多核并行执行，输出 Makespan（主指标）、总额外数据搬运量和 Cache 命中率（次指标）。根据是否具备核间同步机制，赛题区分两种硬件场景：

**场景 A**（无核间同步）：一个 Task 只能包含一个子图，同一核上的 Task 串行执行且核内缓存被清空，所有跨子图数据都经 DDR 中转；同核 Task 切换等待 100 cycle，跨核前驱完成后等待 1000 cycle。

**场景 B**（有核间同步）：同一核心的全部子图合并为一个 Task，同核子图直接复用 L1/UB 中的数据；跨核依赖由源核 COPY_OUT、500 cycle 同步延迟和目标核 COPY_IN 完成。

在此基础上，赛题提出三个问题：

**问题 1：** 在场景 A 下建立多核切图与调度模型并设计求解算法，以缩短 Makespan 为主要目标、兼顾总额外数据搬运量，要求在 2～5 核范围内稳定、高效地求解；正文给出 1～5 核的平均加速比折线图，附录逐用例列出 Makespan 与总额外搬运量。

**问题 2：** 在场景 B 下，在严格满足 L1/UB 容量约束的前提下进一步缩短 Makespan、减少额外搬运，输出内容与问题 1 相同。

**问题 3：** 在场景 B 的基础上引入共享只读 L2 Cache，研究其容量与带宽对切图与调度的影响并设计算法；给出 1～5 核下无 L2 与只读 Cache 两种配置的对比曲线，以及相同核数下只读 Cache 相对无 L2 的加速比（无 L2 的 Makespan 除以只读 Cache 的 Makespan），附录逐用例列出两种配置的 Makespan、额外搬运量与命中率。

**加速比口径。** 单核基准 Makespan 由核内调度算法在整图上计算，单核加速比定义为 1；$N$ 核加速比为 $SU_N=MK_1/MK_N$。平均加速比取 100 个用例加速比的算术平均。由于核内调度是启发式的，单核基准本身并非最优，因此可能出现加速比大于核数的现象（[@sec:bound]给出机理）。

## 问题分析 {#sec:analysis}

三个问题共享同一组决策——切图、分核、同核排序——且三者相互牵制：切图改变子图规模、并行空间与通信边界；分核决定负载均衡与跨核依赖的数量；同核顺序又影响依赖等待、张量驻留时长与换入换出。即便去掉通信、容量与带宽，把独立任务分到同构机器上使 makespan 最小已是 NP-难问题（[@sec:complexity]），因此本文不追求精确解，而是在“单用例求解时间远小于官方评估时间”的预算内稳定逼近理论下界。三个问题的差异与联系见[@tbl:diff]。

: 三个问题的差异与联系 {#tbl:diff widths=2.2,3,3,3}
| 项目 | 问题一（场景 A） | 问题二（场景 B） | 问题三（场景 B + L2） |
|:---|:---:|:---:|:---:|
| Task 的组成 | 一个子图 | 一个核心的全部子图 | 同问题二 |
| 同核子图边界 | 经 DDR 往返，产生搬运 | 零搬运，只决定执行顺序 | 同问题二 |
| 跨核依赖代价 | 1000 cycle，须等全部前驱 Task | 500 cycle，另有申请序停摆 | 同问题二，复读可由 L2 吸收 |
| 子图粒度倾向 | 偏粗 | 中到细 | 中到细 |
| 首要优化量 | 同步层次数与 Task 串行级数 | 负载均衡与跨核依赖后置 | 负载均衡与 Cache 命中 |

### 问题一的分析

场景 A 中子图就是 Task，同核 Task 严格串行、彼此之间不保留缓存数据，因此每一条子图边界都要经 DDR 往返一次，跨核依赖还要额外等待 1000 cycle。这使问题一的难点落在“粒度”上：子图切得越细，边界搬运和 Task 切换越多；切得越粗，单个 Task 越可能超出 L1/UB 容量而触发换入换出，同时核间并行也越少。另一方面，一个 Task 必须等其全部前驱 Task 完成才能激活，跨核依赖链的级数直接串行累加到 Makespan 上。因此问题一需要：（1）一个能刻画 Task 激活与边界搬运的时序模型，用来比较不同粒度；（2）一种让跨核依赖级数尽量少的子图构造；（3）在上述构造之外调整 Task 粗细的局部改进手段。

### 问题二的分析

场景 B 把同一核心的子图合成一个 Task，同核边界不再产生搬运，切图在核内只剩“决定执行顺序”这一个作用，跨核搬运量则只取决于分核。但场景 B 引入了两个新问题：其一，跨核依赖虽然只有 500 cycle 的名义延迟，核内调度的全局申请序却可能让一个未就绪的跨核 COPY_IN 堵住整个核心（[@sec:facts]事实 3），必须把依赖远端数据的算子在时间上往后放；其二，同一 Task 内所有子图共享 L1/UB，核内顺序决定了同一时刻有哪些张量驻留在片上，顺序不当会引发大量换入换出。问题二因此是“分核决定通信、顺序决定驻留”的两层问题，需要在问题一框架上增加直接控制核内驻留的排序手段。

### 问题三的分析

问题三在场景 B 上增加共享只读 L2。要回答“容量和带宽如何影响切图与调度”，首先要弄清命中从哪里来：评估器的 Cache 只服务 COPY_IN、按 FIFO 淘汰、在发射时判定命中、在搬运完成时写入。由此可以推出，命中只可能来自同一张量被多个核心各自读入，或同一核心对同一张量的再次读入；命中字节的上界由计算图中可共享的复读量决定，能否达到则取决于读者之间的时间间隔。问题三需要把命中折算进分配代价，使“把被多核共享的张量复制到多个核心”从纯粹的损失变为可以承受的代价，并通过对比实验与灵敏度分析说明 L2 容量、带宽的作用边界。

## 技术路线 {#sec:route}

本文的技术路线如[@fig:roadmap]所示，共五个环节，各环节的内容与对应章节如下。

### 机理分析

逐行解析官方评估器，归纳出决定模型形态的五条实现事实（[@sec:facts]），其中“全局申请序导致整核停摆”是本文算法设计的出发点；同时提取 100 个测试用例的结构特征，判断并行潜力、带宽压力与容量压力的量级（[@sec:data]）。

### 统一建模

把二部图收缩为算子级 DAG，建立以切图、分核、排序为决策变量、以九条硬约束为约束、以官方 Makespan 为目标的统一优化模型，给出理论下界与超线性加速的来源；进而定义跨核同步层次，把可行性写成构造性定理（[@sec:feasible]）。

### 算法设计与问题求解

设计三个问题共用的四阶段算法 CAP-LS（Communication-Aware Partitioning with Level Stratification），三个问题只在代价权重、候选集合与 L2 折算三处不同：问题一加入 Task 级时序模型与代理驱动退火（第 5 章），问题二加入单算子子图与容量感知表调度（第 6 章），问题三加入命中模型与 Cache 感知代价（第 7 章）。

### 检验评价

在全部 100 个用例上做基线对比、消融实验、粒度与硬件参数灵敏度分析、理论下界差距分析和代理模型可靠性检验（第 8 章），并用官方命令行脚本逐一复核最终方案。

# 模型假设 {#sec:assume}

（1）**评估器即真值假设。** 模型推断与官方评估器行为冲突时，一律以评估器为准；文中上报的 Makespan、额外搬运量与命中率全部由官方脚本在 `data/config.txt` 固定配置下给出，解析模型只用于搜索内部排序。这一假设保证了结论与赛题评分口径一致。

（2）**核内调度固定假设。** 核内 Step1～Step3 是给定的确定性过程，方案只能通过子图划分与子图顺序间接影响它。赛题不允许修改核内调度，因此模型把它视为“子图序列 → 算子顺序与换入换出”的确定映射。

（3）**核心同构假设。** $N$ 个核心的计算能力、流水线结构与私有缓存容量完全相同，因此分核只需考虑负载与通信，不必考虑核心差异。

（4）**DDR 公平共享假设。** $n$ 个在途 DDR 搬运各得 $1/n$ 的带宽，搬运加入或完成时重新分配，与多核评估器的带宽池一致。

（5）**流水线独占假设。** 每核每条流水线同一时刻只有一条在飞指令，四条流水线之间可以并行，Cube 与 Vector 计算可以相互重叠。

（6）**只读 L2 语义假设。** 仅 COPY_IN 可以命中，命中键为写入片上的逻辑张量编号；未命中的读取在完成时写入 Cache，按 FIFO 淘汰且命中不刷新顺序；大于容量的张量不缓存；L2 与 DDR 的带宽池相互独立。

（7）**搬运时长假设。** 一次搬运的参考时长为字节数除以有效带宽（命中 250 B/cycle，未命中 60 B/cycle），实际时长由带宽池公平共享后的剩余工作量决定。

（8）**求解预算假设。** 单用例单候选的构造时间应远小于一次官方评估，算法不对“切图 × 分核 × 排序”做穷举；大图的官方评估较慢，允许以解析代价在候选之间预筛。
