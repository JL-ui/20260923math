## 二、代码层面可选调整（不影响修订稿成立）

### 4. 标准流程不保证加速比 ≥ 1 与随核数单调不降

标准流程中 case_016 在 8 个配置上加速比略低于 1（最低 0.9992），$\mathrm{MK}_N>\mathrm{MK}_{N-1}$ 在三个问题上分别出现 33、26、21 次。正文 8.2 节缺点（2）和 8.3 节改进方向（1）已如实写出，并在 7.7 节给出加入“整图单核 + 本流程 $N-1$ 核嵌入”两个固定候选后的推算均值（问题一 1.76、2.45、3.15、3.67；问题二 2.05、2.87、3.60、4.20；问题三 2.06、2.87、3.65、4.25）。

若要写进程序：在 `experiment.run_portfolio` 的候选列表末尾加入这两个方案，然后重跑主实验并重算口径：

```bash
python solution/run_experiments.py --stage main --jobs 16
python paper/v3/tools/std_caliber.py && python paper/v3/tools/figs_data_v3.py && python paper/v3/tools/build_v3.py
```

改完后正文的均值会随之变化（由占位符自动更新），8.2 节缺点（2）需要改写。

### 5. 择优只比较 Makespan，与字典序目标式不完全一致

第 3 章的字典序目标式是“Makespan 优先、额外搬运量其次”的字典序目标，但 `run_portfolio` 在 Makespan 相同时取先评估的候选。在 1184 个配置中，有 21 个存在 Makespan 相同但额外搬运量更小的候选。正文已在 8.2 节缺点（3）写明。若要一致，把择优键改为 `(makespan, added_copy_bytes)` 后按第 4 条的命令重跑。公式本身不需要改。

### 6. 问题三在部分配置上慢于问题二

标准流程下问题三有 24/400 个配置慢于问题二（最大 21.03%，case_040，$N=5$），其中同一方案的 FIFO 时序效应只占 3 个（最大 0.092%），其余来自两次求解选出的方案不同。正文 6.5.4 节已分两层说明。若要消除，把问题二的标准流程方案作为问题三的固定候选（跨场景候选复用），需要改代码并重跑问题三主实验。

### 7. 未命中来源拆分基于离线方案

6.5.3 节“约 60% 的未命中来自并发首读与 FIFO 淘汰”取自 `results/l2_sources.json`，该脚本（`solution/l2_sources.py`）对 `results/final.csv` 中的离线方案做完整评估。正文已注明口径。若要改为标准流程方案，需要把脚本的输入换成 `paper/v3/data/final_standard.csv` 后重跑（问题三 400 个配置的完整评估）。
