%% TITLE: 基于跨核同步层次分层的通用 NPU 多核切图与调度
%% KEYWORDS: 多核 NPU；计算图切分；跨核同步层次；容量感知表调度；只读 L2 Cache；启发式搜索

::: abstract
多核 NPU 执行一张计算图时，需要联合确定切图、分核与同核子图顺序。该问题以算子到子图的映射、子图到核心的映射和各核心上的子图顺序为决策变量，以 Makespan 为主目标、总额外数据搬运量为次目标，以官方评估程序的输出作为最终评价口径。

解析评估程序后发现，核内调度对申请片上张量的算子施加全局申请序，排在核内序列前部而数据尚未到达的跨核 COPY_IN 会使整个核心的四条流水线同时等待。据此定义跨核同步层次 $r(v)$，以“核心—层次”等价类构造子图并按层次与核心的字典序编号，使算子覆盖、子图商图无环和同核顺序合法等结构性约束由构造保证。求解采用 CAP-LS 算法：先做通信感知的无环分块和块级核心分配的局部搜索，再按同步层次形成子图，由评估程序在预定义候选中择优。

问题一（场景 A）中每个子图单独构成 Task。建立 Task 级时序模型，分析子图粒度在边界搬运与换入换出之间的折中，并以代理驱动的模拟退火调整 Task 粒度。在 100 个用例上，$N=2\sim5$ 的平均加速比为 @@P1_MEAN_LIST@@，单个（用例，核数）配置的求解时间中位数为 @@P1_RT_MED@@ s。

问题二（场景 B）中同核子图边界不再产生搬运，切图主要决定核内执行顺序。对单生产核中间张量和图输入张量，跨核搬运可写成以张量字节为权的 $(\lambda-1)$ 超图割；另增加单算子子图与容量感知表调度候选，以控制片上驻留。平均加速比为 @@P2_MEAN_LIST@@。问题三在场景 B 上加入共享只读 L2，由 FIFO 规则推出命中只来自多核复读与同核重复读入，并把预测命中字节折算进分配代价。只读 Cache 配置的平均加速比为 @@P3_MEAN_LIST@@；同一方案在无 L2 与只读 Cache 下的 Makespan 之比，在 $N=1\sim5$ 时平均为 @@L2SAME_LIST@@。

以上结果均来自同一套标准求解流程，消融、基线与灵敏度实验产生的方案不参与结果选择。$N=4$ 时，标准流程相对最强基线（通信聚类）的平均加速比在三个问题上分别高 @@VSB4_P1_REL@@、@@VSB4_P2_REL@@、@@VSB4_P3_REL@@；在以单一配置为基准的事后消融中（问题一为 @@ABL_P1_NCASE@@ 个用例），去掉同步层次分层后三个问题的平均加速比变化 @@ABL_P1_NO_LEVEL@@、@@ABL_P2_NO_LEVEL@@、@@ABL_P3_NO_LEVEL@@，在单项机制中影响最大。在 @@SENS_CASES@@ 个用例、$N=4$ 的子集上，L2 容量与带宽在所测范围内对 Makespan 的影响不超过 0.2%。
:::
