# 问题重述与问题分析 {#sec:ch1}

## 问题背景 {#sec:bg}

神经网络模型的规模持续增长，单个 AI 核心受制造成本、功耗与散热的限制，难以独立满足算力需求，多核 NPU 因而成为提升并行度与能效的常用架构[[ascend]]。在多核 NPU 上运行一个网络，编译器要把计算图划分为若干子图，把子图分配到各个核心，并确定每个核心上子图的执行顺序。子图切得过细，跨核数据搬运与同步增多；切得过粗，并行空间不足，单个核心还可能因片上缓存装不下而频繁换入换出。

赛题给出的多核 NPU 由 $N$ 个同构 AI 核心和共享片外主存 DDR 组成，硬件结构与固定参数见[@fig:hardware]。每个核心有 Cube 矩阵单元（`PIPE_M`）、Vector 向量单元（`PIPE_V`）和两类搬运单元（`PIPE_MTE2` 负责 DDR→L1/UB 与 UB→L1，`PIPE_MTE3` 负责 L1/UB→DDR 与 L1→UB），以及私有的 L1（512 KB）和 UB（128 KB）。四条流水线可以并行，每条流水线同一时刻只执行一条指令。所有核心公平共享 60 B/cycle 的 DDR 总带宽；问题三另加一个所有核心共享、带宽独立于 DDR 的只读 L2 Cache（1 MB，250 B/cycle）。

![多核 NPU 硬件结构与本题固定配置](figures/v2/fig_hardware.png){#fig:hardware width=15}

待调度对象是一张有向无环计算图 $G=(V,E)$，$V=T\cup O$ 由张量节点集 $T$ 和操作节点集 $O$ 组成，边只允许“张量→操作”或“操作→张量”。张量带有存储位置 `pos`（DDR、L1 或 UB）与字节数 `size`；操作带有类型 `op`、所在流水线 `pipe` 与周期数 `cycles`。图的输入、输出张量位于 DDR，中间张量位于核内缓存。以分块矩阵乘为例，每个数据块依次经历“COPY_IN 搬入—Cube 计算—COPY_OUT 写回”，计算图由大量这样的分块计算链交织而成。

与本题相关的研究主要有三类：以割边或超图连通度为目标的图划分[[metis,catalyurek]]及要求商图无环的有向无环划分[[herrmann]]；深度学习计算图在多设备上的切分与放置[[mirhoseini,jia,alpa,tangram]]；带通信代价的 DAG 调度与整体同步并行（BSP）模型[[kwok,valiant,papp25]]。这些方法的代价模型多以通信量或实测时间为依据；本题的成绩则由一个确定的评估程序给出，其中核内调度的“全局申请序”与只读 FIFO 共享 Cache 属于通用模型通常不考虑的机制，需要先从评估程序中读出，再纳入模型。

## 问题重述 {#sec:restate}

一个多核调度方案包含两部分：**切图方案** `node_to_subgraph`，为每个非 COPY_IN/COPY_OUT 操作指定子图编号；**子图调度方案** `core_schedules`，为每个核心列出其上子图的执行顺序。方案须满足：映射覆盖全部核内操作，子图依赖图无环，同核子图顺序不违反依赖。官方评估程序（下文简称评估器）据此按场景规则重建跨子图的数据搬运，用固定的核内调度流程（Step1 确定拓扑序，Step2 在容量不足时插入换入换出，Step3 在四条流水线上排布）确定每个 Task 内的算子顺序，再在共享带宽下模拟多核并行执行，输出 Makespan（主指标）、总额外数据搬运量和 Cache 命中率（次指标）。按是否具备核间同步机制，题目区分两种硬件场景。

**场景 A**（无核间同步）：一个 Task 只包含一个子图；同核 Task 串行执行，Task 之间不保留核内缓存数据，所有跨子图数据都经 DDR 中转；同核 Task 切换等待 100 cycle，跨核前驱完成后等待 1000 cycle。

**场景 B**（有核间同步）：同一核心的全部子图合并为一个 Task，同核子图直接复用 L1/UB 中的数据；跨核依赖由源核 COPY_OUT、500 cycle 同步延迟和目标核 COPY_IN 完成。

题目要求解决三个问题。

**问题 1：** 在场景 A 下建立多核切图与调度模型并设计求解算法，以缩短 Makespan 为主要目标、兼顾总额外数据搬运量，要求在 2～5 核范围内稳定、高效地求解；给出 1～5 核的平均加速比折线图，并逐用例列出 Makespan 与总额外搬运量。

**问题 2：** 在场景 B 下，在严格满足 L1/UB 容量约束的前提下进一步缩短 Makespan、减少额外搬运，输出内容与问题 1 相同。

**问题 3：** 在场景 B 的基础上引入共享只读 L2 Cache，研究其容量与带宽对切图与调度的影响并设计算法；给出 1～5 核下无 L2 与只读 Cache 两种配置的对比曲线，以及相同核数下只读 Cache 相对无 L2 的加速比，并逐用例列出两种配置的 Makespan、额外搬运量与命中率。

**加速比口径。** 单核基准 Makespan 由核内调度流程在整图上计算，单核加速比记为 1；$N$ 核加速比为 $\mathrm{SU}_N=\mathrm{MK}_1/\mathrm{MK}_N$，平均加速比取 100 个用例加速比的算术平均。核内调度是启发式的，单核基准本身并非最优，因此加速比可能大于核数（[@sec:bound]）。

## 问题分析 {#sec:analysis}

三个问题共享切图、分核、同核排序三项决策，三者相互牵制。切图改变子图规模和通信边界；分核决定负载分布和哪些依赖变成跨核依赖；同核顺序影响依赖等待、张量驻留时长与换入换出。即使去掉通信、容量与带宽，只把独立任务分到两个同构核心上使完成时间最短，其判定问题已是 NP-完全的（[@sec:complexity]）。100 个用例中最小的图有 @@FT_NOPS_MIN@@ 个可切分算子，最大的有 @@FT_NOPS_MAX@@ 个，对切图、分核、排序做枚举并不可行，因此采用“构造可行解 + 局部搜索 + 评估器择优”的启发式路线。三个问题的差别见[@tbl:diff]。

: 三个问题的差异与联系 {#tbl:diff widths=2.2,3,3,3}
| 项目 | 问题一（场景 A） | 问题二（场景 B） | 问题三（场景 B + L2） |
|:---|:---:|:---:|:---:|
| Task 的组成 | 一个子图 | 一个核心的全部子图 | 同问题二 |
| 同核子图边界 | 经 DDR 往返，产生搬运 | 不产生搬运，只影响执行顺序 | 同问题二 |
| 跨核依赖代价 | 等待 1000 cycle，且须等全部前驱 Task | 同步 500 cycle，另受全局申请序影响 | 同问题二，重复读取可能命中 L2 |
| 子图粒度倾向 | 较粗 | 中到细 | 中到细 |
| 主要优化量 | 跨核依赖级数与 Task 串行 | 负载均衡、跨核依赖后置、片上驻留 | 同问题二，另加 Cache 命中 |

场景 A 中子图就是 Task，同核 Task 严格串行、彼此不保留缓存数据，每一条子图边界都要经 DDR 往返一次，跨核依赖还要额外等待 1000 cycle。子图切得越细，边界搬运和 Task 切换越多；切得越粗，单个 Task 越可能超出 L1/UB 容量而触发换入换出，核间并行也越少。一个 Task 须等全部前驱 Task 完成才能激活，跨核依赖链的级数会串行累加到 Makespan 上。仅用“负载均衡 + 少切边”的静态目标，无法反映这种逐级累加的等待，所以问题一需要一个能描述 Task 激活时刻与边界搬运的时序模型，用它比较不同粒度，并在构造出的方案上调整 Task 粗细。

场景 B 把同一核心的子图合成一个 Task，同核子图边界不再产生搬运，继续细化子图不会增加同核搬运，切图的主要作用转为控制核内执行顺序；跨核 COPY 的数量则主要由核心分配决定。跨核依赖的名义延迟只有 500 cycle，但评估器的全局申请序可能让一个数据尚未到达的跨核 COPY_IN 堵住整个核心（[@sec:facts]），依赖远端数据的算子需要在时间上后移。同一 Task 内所有子图共享 L1/UB，核内顺序决定同一时刻有哪些张量驻留在片上，顺序不当会引发大量换入换出。基于这些特点，问题二分别从核心分配和核内排序两个层面进行优化。

问题三在场景 B 上增加共享只读 L2。评估器的 Cache 只服务 COPY_IN，按 FIFO 淘汰，在发射时判定命中、在搬运完成时写入。由此推断，命中只可能来自同一张量被多个核心各自读入，或同一核心对同一张量的再次读入；命中字节的上限由图中可共享的复读量决定，能否达到则取决于各次读取之间的时间间隔。L2 改变了“把一个张量复制到多个核心”的代价，问题三需要把这一变化反映到分核代价中，并分别说明 L2 对最终性能和对同一方案的影响。

## 技术路线 {#sec:route}

技术路线见[@fig:roadmap]。第 2 章区分评估规则与建模假设。第 3 章从评估器实现中归纳决定成绩的机制（[@sec:facts]），建立三个问题共用的优化模型，并以跨核同步层次构造可行子图。第 4～6 章给出 CAP-LS（Communication-Aware Partitioning with Level Stratification）求解算法及其在三个问题上的调整，差别集中在代价权重、候选集合与 L2 折算三处。第 7 章在 100 个用例上做基线对比、事后消融、灵敏度分析与代理可靠性检验。
